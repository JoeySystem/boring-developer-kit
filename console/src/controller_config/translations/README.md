# 修改界面文案

日常只编辑同目录的 **[ui_text.json](ui_text.json)**。中文、英文和日语放在一起，便于对照和缩短按钮、标签或说明文字。

1. 搜索界面上当前显示的文字，找到对应条目。
2. 修改 `zh_CN`（简体中文）、`en_US`（英文）或 `ja_JP`（日语）右边的文字。
3. 保存为 UTF-8，关闭并重新启动**这份源码运行的应用**，查看修改效果。无需运行 Qt 翻译编译工具。

例如，可以将下面条目的三种显示文字改成更短的版本：

```json
"仅保存本地草稿": {
  "source": "仅保存本地草稿",
  "zh_CN": "存草稿",
  "en_US": "Save Draft",
  "ja_JP": "下書きを保存"
}
```

上面只是编辑示例；实际文案库已做过一轮中英文精简。`source` 保留原文作为查找标识，界面显示当前语言对应的值。日语已加入设置页和菜单的语言选择，切换后会保存。

## 编辑时注意

- **只修改 `zh_CN`、`en_US` 和 `ja_JP` 的值。** 外层名称和 `source` 是程序使用的固定查找标识，虽然看起来也是中文，但不要修改。`locations` 是源码位置提示，无需维护；代码变动后行号可能变化。
- `messages` 是固定文字；`dynamic` 是带数量、状态等内容的句子。动态句子中的 `{v1}`、`{v2}` 等代表程序填入的值，可调整顺序，但不要改名或删掉。三种语言需保留相同的占位符。
- 使用 `\n` 换行，文字中的英文双引号写成 `\"`。保留 JSON 的引号、逗号和括号，不要添加注释或末尾多余的逗号。
- 同一个条目可能用于多个位置，修改后会一起更新。需要不同页面使用不同措辞时，再由开发拆分标识。
- 按钮、说明、状态和确认弹窗已做过中英文精简，并补充了常用界面的英文。日语以英文为基础完成本地化；英文中尚未翻译的内部报错依据中文原意补译。先缩短文案，再预览窄窗口；宽度、换行和布局需要在界面组件中调整。请保留操作后果、时长、容量限制和“尚未验证”等状态区别。
- `LIGHT`、`HAPTIC`、`SCREEN` 等点阵风格标题沿用原组件的 ASCII 字符限制，可缩短英文，不要直接换成中文、日文或表情；这些标题若要使用其他文字，需要同时调整标题组件。普通按钮、说明和标签支持中文、英文和日语。
- 用户填写的配置名称、提示词正文、脚本路径、设备实时值不应通过文案库翻译。系统原生对话框内置文字由 Qt／操作系统管理。固定品牌标识和明确跳过翻译的技术信息继续沿用原行为。
- 修改源码文案不会改变已经安装的官方应用；交付新安装包时仍需重新构建应用。本次未更换或发布安装包。

## 检查与维护

在 `console` 目录，使用运行应用的 Python 环境检查 JSON 和占位符：

```bash
.venv/bin/python -m controller_config.text_catalog
```

Windows 使用 `.venv/Scripts/python.exe`。

`text_rules.json` 只负责将已有动态字符串关联到文案条目，日常改文案不需要编辑。原 `.ts` / `.qm` 文件保留作历史对照，**应用已不再读取它们**，请勿在那里修改翻译。打包脚本直接校验并携带 JSON。

程序仍通过原来的语言接口查找文案，页面代码中的原文保留为查找标识，避免大范围重写界面。将来增加新的语言时，给所有条目添加相同的语言字段，并加入文件顶部的 `languages` 列表及程序的语言选择注册；校验会检查新增语言是否完整。
