# 恢复失败时怎么判断

先退出 Console，再使用本工具。当前工具只操作 USB 固件更新通道，不涉及蓝牙；只有灯闪并不能证明这个通道一定失效。

| 看到的情况 | 下一步 |
| --- | --- |
| DMG/.app 无法打开 | 确认 M 系列 Mac。本版未做 Apple 公证；按系统允许的“隐私与安全性 → 仍要打开”流程处理。也可解压源码，用 Python 3.13 虚拟环境运行。不要关闭 Gatekeeper。 |
| 缺少 Python 或依赖 | DMG 不要求安装 Python。源码方式按 README 建立虚拟环境，只在虚拟环境安装 requirements.txt。 |
| 没有发现设备 USB 接口 | 数据线直连，换线或换接口后再扫一次。灯亮不等于有数据连接。仍无接口时保存诊断，联系售后。 |
| 端口被占用 | 退出提示中对应的 Console/串口程序，等待自动扫描恢复。不要同时运行多个刷机程序。 |
| 发现接口，但 HELLO 或能力读取超时 | 说明看得到接口，但尚未建立恢复协议。保存诊断；检查具体固件/连接问题，不能把扫描结果当作已可刷写。 |
| 传输中断 | 保留工具窗口，现有流程会按同一序列号尝试重连。显示失败后再依据日志处理，不要盲目重复。 |
| 刷写结束，重启或版本回读失败 | 不算恢复完成；核对实际连接和日志，不能跳过回滚检查。 |
| 固件已恢复，但官方记录登记失败 | 设备恢复与本机记录是两步。查看权限/配置文件具体错误；保留原 Console 记录，不覆盖整个偏好文件。 |
| Console 仍显示来源未确认 | 必须在运行恢复工具的同一 Mac/账户，先退出工具再重开官方 Console。核对 build_id 和签名记录；不要伪造版本或修改公钥。 |

工具不能从完全不可用的 USB 通道凭空恢复硬件。用户无需拆机或操作 BOOT；无法恢复时由售后继续处理。

## 提供给售后或 AI 的材料

- 系统版本、Mac 芯片、Console 版本。
- 工具页面的最后一条错误，以及“保存诊断信息”生成的 JSON。
- 是否改过固件、是否在刷写中断电，不知道则写未知。
- 是否找到 USB 端口、是否被其他程序占用。

诊断文件保存在本机，不自动上传。公开 Issue 前可隐去本机用户名、目录和设备序列号；不要上传个人提示词、完整配置备份或其他私人文件。
