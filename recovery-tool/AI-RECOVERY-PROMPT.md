# 工具用不了时，把这段交给 AI

适用于 Codex、Claude Code 等能读取本地文件、运行命令的开发工具。普通聊天网页只能给指导，不能直接操作你的 USB 设备。

先克隆本仓库，在 `recovery-tool/` 目录启动 AI，并按 README 下载解压 `BORING-MIST-20261118.01-firmware-package.zip`。有工具生成的记录文件就一并交给 AI；公开发 Issue 前检查其中的设备序列号和本机路径。

下面整段可以直接复制。不知道的项写“未知”，不要为了填信息反复刷机。

```text
请帮我实际排查并更新 BORING MIST，而不是只给通用建议。

我的情况：
- 电脑系统和芯片：〔填写或由你读取〕
- 设备当前表现：〔例如左上角灯一直闪、屏幕不亮〕
- 工具表现或报错：〔填写〕
- BORING Console 版本：〔例如官方 0.2.3〕
- 我是否修改过固件：〔是/否/未知，简述〕
- 记录文件路径：〔有则填写，无则写没有〕
- 固件包目录：〔解压后的路径〕

当前目录是 BORING MIST 固件更新与校准工具源码。我授权你在本机读取排查所需的信息、修改此工具并运行验证；在唯一目标设备明确、固件包核对和硬件匹配通过后，通过 USB 执行更新。不要操作其他设备。

我知道工具会清空三个蓝牙槽位、把两个出厂 Profile 的第 8 键设为单击说话双击发送，并重新校准摇杆。用户不能拆机或接触 BOOT，不要把按 BOOT 当作操作步骤。

请先读 README.md、AGENTS.md、TROUBLESHOOTING.md，再结合实际报错行动：

1. 分清是程序打不开、依赖缺失、USB 没被识别、端口被占用，还是设备的 HELLO/更新协议不响应。检查系统版本、已有记录、串口列表及占用者。不要把“只有灯闪”直接归因于没电、操作失误或固件坏了。
2. 打包程序打不开时，优先在隔离的 Python 虚拟环境按 README 用源码运行同一工具，不要要求关闭系统安全保护，不要改全局 Python。
3. 端口被 Console 等程序占用时，提示我退出对应程序；不要杀掉无关进程。完全找不到 USB 时，指导我直连、换线或换接口后再看结果。没有协议响应时，明确告诉我改电脑端工具不一定能救回这台设备。
4. 只有记录或调用链指向具体问题时才改代码，例如串口选错、解析问题、某一步等待确实不够。做最小修改，为这个失败补一个有意义的测试。不要无依据加大所有超时、死循环重试、关闭版本/硬件/哈希校验，或把失败改成成功。改完运行测试再用工具验证。
5. 只使用固件包里原有的官方签名镜像。不要改它的二进制、build_id、清单或信任公钥，不要生成新密钥冒充官方签名。不得擦除整片 Flash、改分区、覆盖身份/NVS、写 eFuse 或尝试生产签发。若确实需要改固件，先解释原因，并说明自改构建不再是官方固件；本轮先不要擅自走这条路。
6. 写入前确认只有一台目标设备，核对硬件和升级能力，使用现有流程，保留断线后按序列号重连、精确版本/分区/回滚状态验证。传输到 100% 不等于更新成功。
7. 完成后请我在设备上确认屏幕、普通按键、旋钮和摇杆，再在电脑上重新配对蓝牙。Console 显示来源未确认时，指导我导入固件包里的 Firmware-BORING-20261118.01.zip。
8. 最后用短句说明：实际原因或尚未确认的原因、改了哪些文件、测试结果、设备是否真的更新成功、还需要我做什么。保留记录。如果没有可用的 USB 通道，请明确停下并建议联系 BORING 售后，不要让我无限重复刷写。

请不要假设故障已经复现。源码测试通过、端口出现或电脑显示已连接，都不能代替实际更新验证。
```

如果正在使用的 AI 没有终端/文件权限，可以补充：“请一次给我一个可执行步骤，先看真实结果再继续；不要一次发一堆无法判断是否适用的命令。”
