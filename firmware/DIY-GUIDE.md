# DIY 修改边界与官方恢复

**只在功能层范围内 DIY。USB 通信、设备身份认证、固件更新、启动与回滚、分区与存储、电源和硬件引脚等基础模块，坚决不要改。不要让 AI 或第三方脚本改动这些部分，也不要关闭现有校验来强行安装。**

下面的“可改”表示适合从哪里开始，不表示改坏一定可以恢复。即使只改一行，越界、死循环或错误内存访问也可能让通信失效。只有设备仍能被控制台通过 USB 正常识别、完成认证并执行固件安装，才具备控制台恢复官方固件的前提。

## 可以优先修改

尽量先通过控制台配置完成。确需修改源码时，每次只改一项，保持数据格式、数量、尺寸和已有取值限制。

| 内容 | 对应源码 | 修改范围 |
| --- | --- | --- |
| 按键名称、既有动作的键码和组合键、配色 | `components/config_store/default_config_matrix12_power_v2.json` | 只改既有映射和允许范围内的配置值；不改 schema、product_id、hardware_id、control_id 或字段结构。默认配置不一定覆盖设备已经保存的配置。 |
| 固定快捷键和标签 | `components/action_engine/claude_code_shortcuts.c`、`eda_shortcuts.c` 中的快捷键数据表 | 保持表结构、长度、按下/释放处理及调用逻辑；不要改 HID 传输。 |
| 现有页面文案、静态图案和配色 | `components/board/mist_glyph_pages.c`、`mist_glyph_assets.c` 及现有图标数据 | 保持原尺寸和资源预算，只改内容；不能据此把整个 board 目录当作任意修改区域。 |

如果只是这些功能表现不符合预期，**且 USB、认证和更新仍正常**，可以通过下文的官方恢复流程替换 DIY 固件。不是所有显示或按键错误都会触发自动回退。

## 需要慎重修改

以下改动可能影响响应速度、按键释放和资源占用。先理解现有实现并测试，不能仅凭 AI 给出的代码就安装：

- **动画节奏、页面切换、新图形资源**：`components/board/mist_display_model.c`、现有动画模型。保持非阻塞，不扩大缓冲区和资源上限，不影响通信轮询。
- **长短按、连击、宏动作、计时逻辑**：`components/action_engine/` 中对应功能模型。必须保留按键释放、取消和退出路径；不要触碰同文件内的待机、关机或升级协调逻辑。
- **功能层新增运算**：不得占满主循环、长时间等待或无界分配内存；新增功能不能阻止设备继续响应控制台。

不确定一段代码是否涉及下方禁止范围，就不要修改该段。优先提出 Issue 描述想实现的功能。

## 坚决不要改

这些文件随源码公开是为了完整编译和理解实现，**不属于普通用户的 DIY 修改范围**。

| 禁止修改的部分 | 真实位置或标识 | 误改后果 |
| --- | --- | --- |
| USB 接口、VID/PID、串行身份、HID/CDC 收发、轮询 | `components/usb_device/`；协议中的 HELLO、PING、版本协商和命令帧 | 控制台可能无法识别、连接或恢复设备。 |
| 设备身份、证书、认证挑战、安全数据 | `components/device_identity/`、`components/config_protocol/device_auth_codec.c`；product_id、hardware_id、序列号 | 认证失效，设备可能无法再使用官方控制台。不得导出、替换、擦除身份数据。 |
| 升级协议、镜像校验、目标槽选择、启动确认与回滚 | `components/firmware_update/`、`components/config_protocol/firmware_update_protocol.c`；FW_BEGIN / DATA / END / STATUS / ABORT | 无法更新，或错误地确认损坏镜像，失去恢复能力。 |
| 分区、启动配置、Flash 参数、构建身份与保护 | `partitions.csv`、`sdkconfig*.defaults`、构建脚本、镜像描述符、安全启动及 eFuse 设置 | 覆盖必要数据或令程序无法启动。不得更改板型、移动或改大分区，不得擦除整片存储。 |
| 电源、开关机、唤醒、充电相关逻辑、GPIO、物理输出上限 | `components/power_control/`、板级驱动、`board_matrix12_power_v2.h`、电池/电量服务及马达/灯光限幅 | 设备可能无法正常开关机或出现硬件异常。不得提高硬件输出上限。 |
| 配置与身份之外的持久化存储机制 | `components/config_store/config_store.c`、`prompt_store/`、`screen_icon_store/`；NVS 命名空间、布局、迁移和擦除操作 | 丢失配置或破坏官方固件兼容性。可调整配置值不等于可修改存储结构。 |
| 启动顺序、主循环、通信和更新服务调度 | `main/app_main.c`、基础任务和看门狗设置 | 卡死、重启或无法响应控制台。不得删掉必要服务、阻塞主循环或提前确认启动成功。 |

**改动上述基础模块可能导致设备无法正常使用，也无法通过控制台恢复。不要尝试。** 编译通过、能生成 ZIP、控制台允许导入，都不能证明这些底层修改安全。

## 安装前与安装后

1. 先保存当前源码、导出重要配置，准备匹配硬件的官方签名维护包及具备恢复功能的官方控制台。
2. 只用本仓库构建入口生成带 `custom-` 编号的 ZIP。保持设备身份和保护机制不变。
3. 通过 USB 连接，确认控制台显示设备已就绪，再选择“导入自定义固件”。导入只检查包，不会立即安装。
4. 确认安装后保持 USB 连接，等待重连和精确构建编号确认，再检查改动功能、按键释放、正常连接与配置。不能只看到屏幕亮起就认定成功。

当前尚未完成完整“安装 DIY → 恢复官方 → 实际功能正常”的实机验收。初次开发可以先阅读、修改和编译；在具备验收条件前，不建议把自定义固件安装到日常使用设备。

## 仍能连接时恢复官方

设备必须仍可通过 USB 连接、认证并执行固件安装。具备相应功能的官方控制台中：

**固件页 → 查看官方版本 → 下载 → 确认恢复官方固件 → 等待重连及版本确认。**

也可以使用“导入官方固件”选择匹配硬件的官方签名包。主动恢复允许选择较低的官方版本；不要关闭签名或硬件校验。控制台 0.1.29 的这一路径已验证到查询、下载、验签和恢复确认后取消，没有据此宣称实际刷写恢复已验收。

恢复会替换 DIY 功能，不会合并你的源码修改。若 DIY 改过存储格式，不能保证旧配置无损兼容。恢复出厂设置会删除配置与配对，不能代替恢复固件。

现有 A/B 机制只会在相应启动失败条件下尝试回到上一可用固件；上一版本不一定是官方固件，也不会识别所有功能错误。**如果设备已无法被控制台正常连接或更新，请停止尝试并联系官方支持。**
