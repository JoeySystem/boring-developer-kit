# DIY 固件包格式：让控制台正确识别、导入与安装

**使用本仓库构建工具自动生成的 `.zip`，在控制台选择“导入自定义固件”。不要上传整个源码 ZIP、单独的 `.bin`、RAR/7z，或者替换官方包内的镜像。** 包格式正确是必要条件，不代表任意用户代码都能正常启动或安全恢复。

## 推荐的生成方法

先按 [固件编译说明](README.md) 激活 ESP-IDF 6.0.2。在仓库根目录执行：

```sh
cd firmware
sh tools/build.sh --target matrix12-power-v2-codex-usb --custom-name mykeys
```

工具完成编译并自动打包，最后会输出 ZIP 的完整路径。对应目标为 BORING MIST / Matrix12 Power V2，不要换成其他板型。生成的文件在：

```text
firmware/artifacts/v0.3.0-alpha.1/matrix12-power-v2-codex-usb/custom-mykeys/
└── 本次构建目录/
    └── custom-mykeys-….zip   ← 在控制台选择这个文件
```

**版本、构建标识、文件大小和 SHA256 都由工具读取实际编译结果生成，不需要手工填写。** 修改源码后重新执行构建；不要只改 ZIP 里的 JSON，也不要只替换 `.bin`。

## ZIP 里面是什么

标准自定义包只有两个文件，直接放在 ZIP 根目录：

```text
custom-mykeys-….zip
├── firmware-manifest.json
└── wmp-matrix12-power-v2-codex-usb-v…-custom-mykeys-….bin
```

- `firmware-manifest.json` 是 UTF-8 JSON 对象，整个 ZIP 中只能有一份此名称的 manifest。
- `.bin` 是本项目生成的 **ESP32-S3 应用镜像**，不是整个存储镜像，也不是任意二进制文件。
- manifest 的 `image` 必须与 ZIP 内镜像文件名完全一致，镜像与 manifest 位于同一目录。工具已安排好，不要另外打包一层源码目录。
- 控制台也支持选择此维护 ZIP 解压后的 `firmware-manifest.json`；配套 `.bin` 必须仍在它旁边。**不要选择编译目录里用于打包的原始 manifest**：它还没有补齐自定义包来源字段。
- ZIP 外部文件名可以作为自己区分版本的名称；识别依据是包内 manifest 和镜像内容，不是外部文件名。

## 控制台检查哪些字段

下表说明现有格式，供理解或排查。以工具输出为准，不建议自己编写维护包。

| 字段 | 自定义包要求 |
| --- | --- |
| `format` | 固定为 `wmp-firmware-update-v1`。 |
| `product_id` | `wired-macro-pad-v1`，同时与镜像和已连接设备相符。 |
| `hardware_id` | 本目标为 `WMP-S3-MATRIX12-POWER-V2`，同时与镜像和已连接设备相符。 |
| `version` | 镜像内实际产品版本，例如 `0.3.0-alpha.1`，不得与镜像不一致。 |
| `image` | 同目录应用镜像的文件名，不是 URL 或绝对路径。 |
| `size` | 镜像实际字节数，JSON 正整数，不是 ZIP 大小，也不是字符串。 |
| `sha256` | 镜像实际 SHA256，64 位小写十六进制字符串。 |
| `build_id` | `custom-` 开头，并实际写入编译出的镜像。前缀之后为 1–57 位英文字母、数字、点、下划线或连字符。使用构建工具生成，不要拿官方镜像改名冒充。 |
| `origin` | 固定为 `custom`。 |
| `validation_state` | 固定为 `built`，不能自行标记为官方验收通过。 |
| `minimum_app_version` | 三段式控制台最低版本；工具默认 `0.1.24`。当前控制台不能低于包的要求，且必须具备“导入自定义固件”入口。 |
| `signature` | **不能出现此字段**，空字符串也不行。官方签名包使用“导入官方固件”，不能混用入口。 |

工具还会记录 `build_target`、`git_commit`、`git_dirty`、`built_at` 等构建信息，保留原值即可。源码 ZIP 没有 Git 信息时会明确标记 `unavailable` 和 `-nogit`，仍可生成合法自定义包。不要为通过检查更改硬件身份或伪造来源。

仅在需要重新打包已有自定义编译结果时，可在 `firmware/` 目录使用：

```sh
python3 tools/pack_custom_firmware.py \
  --manifest /path/to/custom-build/firmware-manifest.json \
  --output /path/to/my-custom-firmware.zip
```

将两个示例路径替换为实际路径。工具只打包已有自定义镜像，不把官方镜像变成 DIY；输出文件已存在会拒绝覆盖。

## 从识别到真正完成安装

1. **选择正确入口**：在控制台固件页选择“导入自定义固件”，选择上述 ZIP。新恢复流程参考官方控制台 0.1.29；仓库旧 0.1.13 安装包不适用于本文流程。
2. **包检查通过**：控制台核对上述字段、镜像格式、内嵌身份、大小和 SHA256。显示自定义来源及包已就绪，只表示检查通过，尚未向设备安装。
3. **设备允许安装**：设备必须通过 USB 正常连接并完成认证，处于可写状态，声明支持固件更新，且镜像大小不超过设备报告的 OTA 上限。若设备要求设备端签名，当前不支持安装自定义固件。不要绕过限制。
4. **用户明确确认安装**：保持 USB 和供电稳定，不要拔线或关闭电源。蓝牙连接可以用于部分查询，但当前安装必须走 USB。
5. **重连与结果确认**：等待控制台确认同一设备、目标版本、精确 custom 构建编号、运行分区和回滚状态。然后检查实际修改功能及配置；进度到 100% 或屏幕亮起都不等于这些检查已经完成。

如果包被拒绝，按提示修正源码、目标或打包步骤后重新生成；不要删除检查或手改身份。如果设备无法正常连接或更新，停止尝试并联系官方支持。

**USB、认证、更新、启动回滚、分区存储、电源和硬件引脚等基础模块坚决不要改。** 保留这些功能是后续正常安装和控制台恢复的前提，详见 [DIY 修改边界](DIY-GUIDE.md)。完整 DIY 安装 → 恢复官方 → 功能正常的实机流程尚未验收，本文不作“包能导入就一定能刷好”的承诺。
