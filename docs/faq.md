# 常见问题

## 现在可以下载 SDK 开始运行吗？

可以下载源码、SDK wheel 和示例。可以直接下载 [0.1.13 M 系列 Mac 测试版安装包](install-console.md)，或从 [控制台源码](../console/README.md) 自行运行 API 1.0 / Runner 宿主；安装包仍是 0.1.13，源码已到 0.1.24，公开适配和验收范围不同。请看 [版本与下载](versions.md)。

## 点击 Code → Download ZIP，为什么不能导入控制台？

这个按钮下载整个仓库源码。应先解压，再选择 examples/extensions 下的单个示例目录导入；完整开发包另带 examples/packages 中的示例 ZIP。整个仓库或开发包不是一个扩展。

## 这是固件开源吗？

现在也公开了 [固件源码](../firmware/README.md)，采用仓库现有非商业许可。修改前必须阅读 [DIY 边界](../firmware/DIY-GUIDE.md)：基础模块坚决不要改，不能保证任意损坏固件都能恢复。完整范围见 [开放范围](scope.md)。

## 我需要自己编译固件或安装 Python 吗？

使用兼容官方安装包时，由宿主携带扩展运行内容；从本仓库运行社区控制台需要准备 Python 开发环境。两条路径都不要求为了运行扩展而自行编译固件。环境准备见 [开始使用](../START-HERE.md)，社区源码运行见 [控制台说明](../console/README.md)。

## 能直接修改旋钮、屏幕、灯光和所有按键行为吗？

不能把首期 SDK 理解为通用硬件控制接口。首期围绕提示词槽位触发、绑定动作和映射提案；原始输入事件、屏幕绘制和设备内部工作模式不在首期接口承诺内。

## 扩展在设备里运行，还是在电脑里运行？

首期扩展在电脑上，由控制台启动和管理。电脑端自定义动作需要相应运行进程在线，不能因为扩展已导入就认为它已经写入固件。

## 扩展显示运行中，为什么实体操作没有执行我的动作？

排查顺序是：先确认控制台连接正常，再确认设备上的触发已经配置好，最后确认该设备、槽位和扩展动作的绑定。导入、启用、就绪和绑定是不同阶段。

若同一触发已绑定内置自动化，它的优先级高于扩展动作。手动试运行成功也不证明实体入口已经配置完成。

## 我只想接管动作，为什么原来的粘贴还会执行？

观察者收到的是事件副本，不阻止默认行为。接管需要声明并绑定扩展动作；动作未就绪、拒绝或未及时接受时，也可能走粘贴回退。详见 [扩展如何工作](extensions-overview.md)。

## 修改了文件，为什么重启扩展仍然执行旧逻辑？

控制台导入的是受管副本。修改原始开发目录后，需要按版本说明替换或重新导入，不能只重启旧副本。详见 [开发流程](development-guide.md)。

## 扩展提交了改键建议，为什么设备还没变？

建议需要用户审阅，批准后进入本地草稿，之后仍需通过控制台确认写入并读回设备。提交提案不等于设备已写入。

## Windows、macOS 和蓝牙是否都支持？

本轮验证目标为 macOS / Python 3.12，实际完成项见 [发布验证](verification.md)。Windows、Linux、Python 3.13、干净电脑、BLE 扩展实体触发不作为默认已验收范围。官方安装版历史结果与社区构建分别记录，见 [兼容说明](versions.md)。

## 可以商用、收费分享或在工作中使用吗？

本次采用 PolyForm Noncommercial 1.0.0，商业复用另行书面授权；没有额外工作场景自用豁免，不出售扩展不等于必然是非商业使用。官方产品既有使用权不因此改变。详见 [使用许可](../LICENSING.md)。

## 可以让官方帮我适配某个软件吗？

可以提交具体场景，但不承诺实现、答疑时间或长期适配。先搜索已有 Issue，同一问题可以补充信息。维护范围见 [SUPPORT](../SUPPORT.md)。

## 我应该上传什么信息来报告问题？

操作系统、控制台 / 固件 / 开发包版本、连接方式、简短复现步骤、预期和实际结果即可；不适用或未知的信息直接说明。只附与问题相关的日志或截图，移除凭据、个人内容和完整设备标识。

不要公开上传整机备份、生产记录或私人提示词库。官方硬件正常使用和售后问题继续通过原有官方渠道处理。
